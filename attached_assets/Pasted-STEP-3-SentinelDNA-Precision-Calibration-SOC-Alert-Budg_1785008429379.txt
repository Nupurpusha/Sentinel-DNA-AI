==================================================
CURRENT PROBLEM
==================================================

The current detector has strong anomaly ranking but produces too many operational alerts.

Current evaluation is approximately:

Precision: 13.7%
Recall: 85.2%
F1: 23.6%
ROC-AUC: ~0.969

True Positives: ~351
False Positives: ~2,210
False Negatives: ~61

The current Isolation Forest uses contamination around 0.05, which contributes to roughly 5% of events being flagged even though the dataset is extremely imbalanced.

The goal of Step 3 is NOT simply to make the metrics look better.

The goal is to convert SentinelDNA into a SOC-oriented prioritization engine that ranks anomalies and gives analysts a small, high-confidence alert queue.

==================================================
ABSOLUTE DATA-LEAKAGE RULE
==================================================

The existing ground-truth `label` field is EVALUATION ONLY.

NEVER use `label` or attack type:

- as an ML feature
- in Isolation Forest training
- in anomaly-score calculation
- in behavioral-deviation calculation
- in risk-score calculation
- to decide risk level
- to rank alerts
- to choose individual predictions
- to determine the operational alert threshold

Ground truth may ONLY be consulted AFTER risk scores/rankings have been generated to calculate offline evaluation metrics.

3. BEHAVIORAL EVIDENCE SCORE
==================================================

Using the behavioral deviation features already implemented in Step 2, calculate an interpretable:

behavioral_deviation_score: 0–100

and:

evidence_count

Evidence may include legitimate existing deviations such as:

- unknown device
- unseen/unusual location
- access outside normal hours
- unfamiliar resource
- unusual authentication method
- authentication failure
- abnormal session duration
- unusual IP/subnet
- abnormal recent access frequency

Do NOT fabricate deviations.

Only use signals derivable from the existing telemetry and identity profile.

One weak deviation should not automatically create a Critical alert.

Multiple independent deviations occurring together should increase confidence.

Example concept:

1 weak deviation
→ low/moderate evidence

3 independent meaningful deviations
→ strong evidence

4+ strong independent deviations combined with a high ML anomaly score
→ potentially High/Critical

The implementation must remain deterministic and explainable.
